# COS-DROP Web — Telegram Web App

Проект объединяет существующего COS-DROP Telegram-бота и Web App в одном процессе и использует одну SQLite-базу. Существующая логика бота сохранена; в меню добавляется кнопка Web App, если задан `WEBAPP_URL`.

## Структура

- `bot.py` — существующий бот, с запуском Web API параллельно polling.
- `webapp_api.py` — API для сайта; проверяет Telegram `initData` и использует тот же `DB_FILE`.
- `web/index.html` — интерфейс COS-DROP с анимациями, кнопки вызывают API.
- `requirements.txt` — зависимости.
- `Procfile` — команда запуска для Railway.

## ВАЖНО: не потеряй базу

1. Перед обновлением сделай резервную копию текущего `cosdrop.sqlite3` через имеющуюся функцию бота или скачай файл с volume.
2. На Railway оставь текущий Volume и его mount path `/data`.
3. В Variables укажи `DB_FILE=/data/cosdrop.sqlite3` — **точно тот же путь**, который использует текущий бот. Не меняй имя файла и не удаляй volume.
4. Не создавай новый volume и не запускай сайт с другим `DB_FILE`. Иначе сайт увидит пустую отдельную базу.
5. Используй один сервис/процесс для бота и Web App. Не запускай второй экземпляр polling-бота с тем же токеном.

## Деплой Railway

1. Распакуй архив и загрузи содержимое папки `COS-DROP-Web` в отдельную ветку/папку репозитория, предварительно сохранив текущий код и базу.
2. Убедись, что в корне репозитория лежат `bot.py`, `webapp_api.py`, `requirements.txt`, `Procfile`, папка `web/`.
3. В Railway используй **существующий сервис и его Volume**. Не удаляй и не пересоздавай сервис/volume без резервной копии.
4. Variables: `BOT_TOKEN` — токен бота; `DB_FILE=/data/cosdrop.sqlite3`; `WEBAPP_URL` пока можно добавить после того, как Railway выдаст публичный HTTPS-домен.
5. Убедись, что Start Command — `python bot.py` (или Procfile worker). Railway должен открыть HTTP-порт через `PORT`.
6. После деплоя проверь `https://ТВОЙ-ДОМЕН/api/health` — ожидается JSON `{"ok": true, "service": "COS-DROP WebApp"}`.
7. В `WEBAPP_URL` укажи этот HTTPS-домен и перезапусти сервис.
8. В BotFather настрой Web App/Menu Button на тот же HTTPS URL, если хочешь запускать его через отдельную кнопку меню. В обычной клавиатуре бота кнопка появится автоматически при заданном `WEBAPP_URL`.

## Telegram Web App безопасность

Сайт должен открываться внутри Telegram. API проверяет подпись `Telegram.WebApp.initData` с помощью токена бота. Не отключай эту проверку для публичного сайта. При открытии URL напрямую в обычном браузере игровые API намеренно ответят `401`.

## Текущее состояние функционала

Включены интерфейс и API для dashboard, кейсов, ежедневного бонуса, инвентаря/продажи, промокодов, рейтинга, казино и дуэлей. Добавлен endpoint заданий; прямое получение доступно только ежедневному заданию, остальные требуют прогресса в существующей игровой логике. Если какие-то старые данные в базе отличаются по схеме, сначала делай backup и тестируй на копии.

## Локальный запуск

PowerShell:

```powershell
py -3.13 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:BOT_TOKEN="ВАШ_ТОКЕН"
$env:DB_FILE=".\cosdrop.sqlite3"
$env:WEBAPP_URL=""
python bot.py
```

Для реальной проверки Telegram авторизации открой приложение через Telegram. Не выкладывай `.env`, токен или настоящую базу в GitHub.
